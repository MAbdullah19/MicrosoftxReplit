---

Three rules for the whole build:

1. **Build in milestone order (§16).** Each milestone ends in a runnable, demoable state. Do not start M4 before M3 passes its acceptance test.
2. **When something is missing (an API key, a contract address), degrade gracefully — never block the build.** §5.3 specifies exactly how. The app must run end-to-end with zero external keys configured.
3. **If this document conflicts with `design.md`, this document wins** (it resolves several under-specified points). If it conflicts with `design-full.md`, ignore `design-full.md` entirely — that is the *scaled* architecture and is explicitly out of scope.
4. Create a context.md at the start and update it at each major milestone to keep track of the progress and context.

## 1. What the product is, in ten lines

A public website where anyone can check whether a phone number, website, or claim is trustworthy.

- **Anyone can read.** No account, no login wall, no cookie banner.
- **To vote you need a passkey + a one-time invite code.** No email, no phone, no name — ever.
- Votes are weighted by a **Bayesian reputation** earned by having been right before.
- Voters state a **confidence**, and are graded by the **Brier proper scoring rule** — honesty is the optimal strategy, and that is a theorem.
- When a claim resolves, the verdict is hashed into a **Merkle tree** and the root is written to **Base Sepolia**.
- A stranger can then **verify that verdict in their own browser against the public blockchain, without trusting our server**.
- An **AI signal** contributes evidence, capped at 15 % of total weight, never a verdict.
- Every score **decomposes into named contributions** shown as a waterfall.

**The three things that must work on demo day:** (1) no PII exists anywhere, (2) the score is explainable, (3) the verdict is falsifiable by a stranger.

## 2. Non-negotiable invariants

Violating any of these breaks the product's core claim. Treat them as assertions, not preferences.

| # | Invariant | Why |
|---|---|---|
| **I1** | `pseudonym_id` is `crypto.randomUUID()`. It is **never** derived from any input. | A hash of an enumerable value is not anonymity. This is the single most important fix vs. the reference project. |
| **I2** | There is **no email column, no phone column, no name column**, anywhere in the schema. | "We have no PII" must be structurally true, not a policy. |
| **I3** | `forum.votes` has **no foreign key to `forum.accounts`**. The primary key is the nullifier. | Dumping the votes table must reveal nothing about who voted. |
| **I4** | All score mutation happens inside the Postgres function `vote_and_rescore()`, in one transaction, with `SELECT … FOR UPDATE` on the claim row. **No read-modify-write from JavaScript.** | Two simultaneous votes must not corrupt the score. |
| **I5** | The `enrolment` schema stores **no reference to any pseudonym**. | Nobody, including us, can link "who redeemed invite #7" to "who owns pseudonym fox-8813". |
| **I6** | Invite codes and backup codes are stored **only** as `argon2id` hashes. Raw codes are shown once and never persisted or logged. | — |
| **I7** | `score` in the canonical record is a **fixed 6-decimal-place string**, never a float. All canonical numbers are strings. | Float serialisation differs across languages; your verifier will silently disagree with your server. |
| **I8** | Merkle leaves use domain separator `0x00`, internal nodes `0x01`. Odd node counts duplicate the last node. | Second-preimage resistance, and cross-implementation agreement. |
| **I9** | AI **cannot resolve a claim** and contributes **zero weight** until at least one human vote exists. | AI is evidence, never judge. |
| **I10** | No secret has a fallback default in code. `process.env.X ?? "some-default"` is forbidden. Crash loudly at boot instead. | A fallback silently becomes the real secret in every misconfigured environment. |
| **I11** | Raw IPs, invite codes, backup codes and session tokens are **never logged**. | — |
| **I12** | "Not enough evidence yet" must never render as "safe" — icon + text + colour, never colour alone. | Safety requirement. We must not become a laundering service for scams too new to be reported. |

## 3. Stack and exact dependencies

**Deviation from `setup.md` §5.3, deliberate:** that document specifies a pnpm workspace deployed to Vercel serverless. **On Replit we use a single `package.json` and a single long-lived Express process** that serves both the API and the built SPA. This matches Replit's execution model (one process, one port) and removes an entire class of monorepo/serverless build failures. Everything else in `setup.md` still applies.

### 3.1 Runtime

- Node.js 20 LTS, TypeScript 5.x, ESM (`"type": "module"`)
- One process. Express listens on `0.0.0.0` at `process.env.PORT ?? 5000`.
- In dev, Vite runs in **middleware mode** inside the same Express process (no second port, no proxy, no CORS).
- In production, Express serves `client/dist` statically and falls through to `index.html` for SPA routes.

### 5.2 `server/env.ts` — fail fast, no fallbacks

```ts
import { z } from "zod";

const required = z.string().min(16);

const schema = z.object({
  NODE_ENV:          z.enum(["development", "production"]).default("development"),
  PORT:              z.coerce.number().default(5000),
  DATABASE_URL:      z.string().url(),
  SESSION_SECRET:    required,
  PEPPER_IDENTITY:   required,
  PEPPER_VOTE:       required,
  PEPPER_NET:        required,
  JOB_TOKEN:         required,
  RP_ID:             z.string().min(1),
  RP_ORIGIN:         z.string().url(),
  RP_NAME:           z.string().default("Attest"),
  // optional — absence switches on a documented degraded mode (§5.3)
  TURNSTILE_SECRET_KEY:    z.string().optional(),
  GEMINI_API_KEY:          z.string().optional(),
  ANCHOR_CONTRACT_ADDRESS: z.string().optional(),
  ANCHORER_PRIVATE_KEY:    z.string().optional(),
  RPC_URL:                 z.string().url().default("https://sepolia.base.org"),
});

const parsed = schema.safeParse(process.env);
if (!parsed.success) {
  console.error("FATAL: invalid environment\n", parsed.error.flatten().fieldErrors);
  process.exit(1);
}
export const env = parsed.data;

export const features = {
  turnstile: !!env.TURNSTILE_SECRET_KEY,
  ai:        !!env.GEMINI_API_KEY,
  chain:     !!(env.ANCHOR_CONTRACT_ADDRESS && env.ANCHORER_PRIVATE_KEY),
};
```

### 5.3 Degraded modes — the app must run with zero optional keys

| Missing | Behaviour in `development` | Behaviour in `production` |
|---|---|---|
| `TURNSTILE_SECRET_KEY` | Skip the check. Log `[degraded] turnstile disabled` **once at boot**. Client hides the widget. | **Reject enrolment with 503.** Never silently disable a bot gate in prod. |
| `GEMINI_API_KEY` | Insert a fixture `ai_signal` (`verdictHint: 'unverifiable'`, `confidence: 0`, rationale `"AI analysis unavailable."`, `weight_contributed: 0`). UI shows the card greyed with "AI analysis unavailable". | Same as dev — the 15 % cap means nothing structural breaks. |
| chain keys | `POST /api/jobs/anchor` marks epochs `status='skipped_no_chain'`. `/verify` returns the record + local proof and the client shows **amber**: *"Verified against our local ledger. Not yet anchored on-chain."* | Same. |

**Never** let a missing key throw a 500 or crash a request path. Surface it in `GET /api/health` instead:

```jsonc
GET /api/health → { "ok": true, "features": { "turnstile": false, "ai": true, "chain": true }, "ledgerHead": 412, "latestEpoch": 1849 }
```

### 7.2 `shared/schema.ts` (Drizzle)

```ts
import { pgSchema, uuid, text, integer, bigint, bigserial, boolean,
         doublePrecision, timestamp, jsonb, smallint, customType } from "drizzle-orm/pg-core";

export const enrolment = pgSchema("enrolment");
export const forum     = pgSchema("forum");

const bytea = customType<{ data: Buffer }>({ dataType: () => "bytea" });

/* ═══ enrolment — stores NO reference to any pseudonym (I5) ═══ */

export const invites = enrolment.table("invites", {
  id:         uuid("id").primaryKey().defaultRandom(),
  codeHash:   text("code_hash").notNull().unique(),   // argon2id(pepper ‖ code)
  issuedBy:   text("issued_by"),                      // 'admin' | 'user' — NEVER a pseudonym
  expiresAt:  timestamp("expires_at", { withTimezone: true }).notNull(),
  redeemedAt: timestamp("redeemed_at", { withTimezone: true }),
  revoked:    boolean("revoked").default(false).notNull(),
});

export const rateLimits = enrolment.table("rate_limits", {
  key:         text("key").notNull(),                 // HMAC(PEPPER_NET, ip) or pseudonym
  action:      text("action").notNull(),
  count:       integer("count").default(0).notNull(),
  windowStart: timestamp("window_start", { withTimezone: true }).defaultNow().notNull(),
}, (t) => ({ pk: primaryKey({ columns: [t.key, t.action] }) }));

/* ═══ forum ═══ */

export const accounts = forum.table("accounts", {
  pseudonymId:    uuid("pseudonym_id").primaryKey().defaultRandom(),  // RANDOM (I1)
  handle:         text("handle").notNull().unique(),                  // 'fox-8813'
  tier:           smallint("tier").default(1).notNull(),              // 1 = guest, 2 = verified
  passkeyId:      text("passkey_id").notNull().unique(),
  passkeyPubkey:  bytea("passkey_pubkey").notNull(),
  passkeyCounter: bigint("passkey_counter", { mode: "number" }).default(0).notNull(),
  repA:           doublePrecision("rep_a").default(1).notNull(),
  repB:           doublePrecision("rep_b").default(1).notNull(),
  points:         integer("points").default(0).notNull(),             // EARNED, not granted
  pointsStaked:   integer("points_staked").default(0).notNull(),
  invitesMinted:  integer("invites_minted").default(0).notNull(),
  createdAt:      timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
});

export const backupCodes = forum.table("backup_codes", {
  pseudonymId: uuid("pseudonym_id").notNull().references(() => accounts.pseudonymId, { onDelete: "cascade" }),
  codeHash:    text("code_hash").notNull(),
  usedAt:      timestamp("used_at", { withTimezone: true }),
}, (t) => ({ pk: primaryKey({ columns: [t.pseudonymId, t.codeHash] }) }));

export const claims = forum.table("claims", {
  id:           uuid("id").primaryKey().defaultRandom(),
  subjectKind:  text("subject_kind").notNull(),        // 'url' | 'phone' | 'text'
  subjectValue: text("subject_value").notNull(),       // normalised
  subjectKey:   text("subject_key").notNull(),         // sha256(kind|value)
  statement:    text("statement").notNull(),
  detail:       text("detail"),
  contentHash:  text("content_hash").notNull(),
  status:       text("status").default("open").notNull(),  // open|verified|refuted|inconclusive|removed
  alpha:        doublePrecision("alpha").default(1).notNull(),
  beta:         doublePrecision("beta").default(1).notNull(),
  score:        doublePrecision("score").default(0.5).notNull(),
  ciLow:        doublePrecision("ci_low"),
  ciHigh:       doublePrecision("ci_high"),
  voterCount:   integer("voter_count").default(0).notNull(),
  author:       uuid("author").references(() => accounts.pseudonymId),
  stableSince:  timestamp("stable_since", { withTimezone: true }),
  resolvedAt:   timestamp("resolved_at", { withTimezone: true }),
  anchorEpoch:  bigint("anchor_epoch", { mode: "number" }),
  createdAt:    timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
  expiresAt:    timestamp("expires_at", { withTimezone: true }).notNull(),
}, (t) => ({
  bySubject: index("claims_subject_idx").on(t.subjectKey),
  byStatus:  index("claims_status_idx").on(t.status, t.createdAt),
```

## 8. Subject normalisation — `shared/subject.ts`

The subject key must be **stable and identical on client and server**. Get this wrong and the same URL produces two different subject pages.

```ts
import parsePhone from "libphonenumber-js";
import { sha256Hex } from "./hash";           // isomorphic sha256 → lowercase hex

export type SubjectKind = "url" | "phone" | "text";

const TRACKING = /^(utm_|fbclid$|gclid$|mc_eid$|igshid$|ref$|ref_src$|si$|s$)/i;

export function normaliseSubject(kind: SubjectKind, raw: string): string {
  const v = raw.trim();
  switch (kind) {
    case "url": {
      let u: URL;
      try { u = new URL(/^https?:\/\//i.test(v) ? v : `https://${v}`); }
      catch { return v.toLowerCase(); }
      u.protocol = "https:";                                  // scheme-insensitive subjects
      u.hostname = u.hostname.toLowerCase().replace(/^www\./, "");
      u.hash = "";
      const keep = [...u.searchParams.entries()]
        .filter(([k]) => !TRACKING.test(k))
        .sort(([a], [b]) => (a < b ? -1 : a > b ? 1 : 0));
      u.search = keep.length ? "?" + keep.map(([k, val]) => `${k}=${val}`).join("&") : "";
      if (u.pathname === "/") u.pathname = "";
      return u.toString().replace(/\/$/, "");
    }
    case "phone": {
      const p = parsePhone(v, "PK");                          // default country; user may type +CC
      if (p?.isValid()) return p.number;                      // E.164, e.g. +923001234567
      const digits = v.replace(/[^\d+]/g, "");
      return digits.startsWith("+") ? digits : `+${digits}`;
    }
    case "text":
      return v.toLowerCase().replace(/\s+/g, " ").replace(/^[^\p{L}\p{N}]+|[^\p{L}\p{N}]+$/gu, "");
  }
}

export function subjectKey(kind: SubjectKind, raw: string): string {
  return sha256Hex(`${kind}|${normaliseSubject(kind, raw)}`);
}

/** Used by the landing-page search box to guess the kind from free text. */
export function detectKind(raw: string): SubjectKind {
  const v = raw.trim();
  if (/^(https?:\/\/|www\.)|^[a-z0-9-]+\.[a-z]{2,}(\/|$)/i.test(v)) return "url";
  if (/^\+?[\d\s()-]{7,}$/.test(v)) return "phone";
  return "text";
}
```

## 9. The scoring engine — `shared/score.ts`

This is the intellectual core. It is about 120 lines. Implement it exactly.

### 9.1 Vote weight

$$w_i = R_i \cdot \big(1 + \ln(1 + s_i)\big)$$

```ts
export function rawWeight(repA: number, repB: number, stake: number) {
  const reputation = repA / (repA + repB);      // R ∈ (0,1)
  const stakeFactor = 1 + Math.log(1 + stake);  // concave — doubling stake ≠ doubling influence
  return { reputation, stakeFactor, raw: reputation * stakeFactor };
}
```

### 9.2 Per-voter cap — with the small-n correction

> **⚠️ Design refinement, read this.** `design.md` §4.1 specifies a flat 15 % per-voter cap. **A flat 15 % cap is mathematically unsatisfiable below 7 voters** (with 3 voters each holds ≥ 33 %), and naïve water-filling would force all weights equal — deleting reputation weighting entirely at exactly the scale we demo at. The effective cap is therefore `max(0.15, 2/n)`: it never binds below ~7 voters, binds loosely between 7 and 14, and reaches the intended flat 15 % from 14 voters onward. It still does its real job — stopping one voter from single-handedly carrying a claim — at every n.

```ts
import { SCORING } from "./config";

/** Iterative water-filling. Returns capped weights, same order. */
export function applyVoterCap(weights: number[]): number[] {
  const n = weights.length;
  if (n === 0) return [];
  const cap = Math.max(SCORING.VOTER_CAP, 2 / n);
  const w = [...weights];
  for (let iter = 0; iter < 32; iter++) {
    const total = w.reduce((a, b) => a + b, 0);
    if (total <= 0) return w;
    const max = total * cap;
    let changed = false;
    for (let i = 0; i < n; i++) {
      if (w[i] > max + 1e-12) { w[i] = max; changed = true; }
    }
    if (!changed) break;
  }
  return w;
}
```

### 9.3 Posterior, score, credible interval

```ts
import { jStat } from "jstat";

export function posterior(supportW: number[], refuteW: number[]) {
  const alpha = 1 + supportW.reduce((a, b) => a + b, 0);
  const beta  = 1 + refuteW.reduce((a, b) => a + b, 0);
  const score = alpha / (alpha + beta);
  const ciLow  = jStat.beta.inv(0.05, alpha, beta);
  const ciHigh = jStat.beta.inv(0.95, alpha, beta);
  return { alpha, beta, score, ciLow, ciHigh };
}

/** P(θ ≥ τ) from the Beta posterior. */
export const pAtLeast = (tau: number, a: number, b: number) => 1 - jStat.beta.cdf(tau, a, b);
export const pAtMost  = (tau: number, a: number, b: number) =>     jStat.beta.cdf(tau, a, b);
```

Prior is `Beta(1,1)` — uniform, "we know nothing", score 0.5. **Do not hand-roll the inverse Beta CDF.**

### 9.4 AI weight

AI contributes to `alpha`/`beta` like a voter, but hard-capped at 15 % of the *total including itself*:

$$w_{ai} \le c \cdot (W_{human} + w_{ai}) \;\Longrightarrow\; w_{ai} \le \frac{c}{1-c} W_{human}$$

```ts
export function aiWeight(humanTotal: number, confidence: number, disputed: boolean) {
  if (humanTotal <= 0) return 0;                         // I9 — AI alone never moves a score
  const c = disputed ? SCORING.AI_DISPUTED_CAP : SCORING.AI_WEIGHT_CAP;
  return Math.min(confidence * SCORING.AI_BASE_WEIGHT, (c / (1 - c)) * humanTotal);
}
```

`verdictHint: 'likely_true'` adds to support, `'likely_false'` to refute, `'unverifiable'` adds nothing.

### 9.5 Brier scoring, reputation, and payout

> **⚠️ Design refinement, read this.** The raw Brier score `Δ = 1 − 2(p−y)²` is `+0.5` for a `p = 0.5` hedge **regardless of outcome**. Used directly for reputation or points, that is a free money pump: hedge on everything, profit forever. We therefore use the **centred** score `Δc = Δ − 0.5`, which makes hedging exactly break-even. Centring is an affine transform, so the rule remains **strictly proper** — the theorem still holds and is still the strongest sentence you can say at the judging table. This also fixes `design.md` §4.4's `20 × stake × Δ` payout, which inflates a 10-point starting balance to dominance in about four votes.

```ts
/** p_true = the voter's stated probability that the claim is TRUE. */
export function pTrue(stance: "support" | "refute", confidence: number) {
  return stance === "support" ? confidence : 1 - confidence;
}

/** Centred Brier. Range [-1.5, +0.5]. Hedging at p=0.5 → exactly 0. */
export function brier(p: number, y: 0 | 1) {
  return (1 - 2 * (p - y) ** 2) - 0.5;
}

/** Points returned for a stake. clamp(1 + 2Δc, 0, 2) × stake. */
export function payout(stake: number, deltaC: number) {
  const m = Math.min(2, Math.max(0, 1 + SCORING.PAYOUT_SPREAD * deltaC));
  return Math.round(stake * m);
}

/** Reputation update. `damped` = true when the crowd graded itself. */
export function updateReputation(a: number, b: number, deltaC: number, damped: boolean) {
  const d = damped ? deltaC * SCORING.CROWD_GRADED_DAMPING : deltaC;
  return {
    a: SCORING.REP_DECAY * a + Math.max(0,  d),
    b: SCORING.REP_DECAY * b + Math.max(0, -d),
  };
}
```

Worked examples (verify these in a unit test):

| Vote | Outcome | Δc | Payout on stake 5 | Reputation |
|---|---|---|---|---|
| p = 0.95, right | ✅ | **+0.495** | 10 (doubles) | a += 0.495 |
| p = 0.95, wrong | ❌ | **−1.305** | 0 (loses all) | b += 1.305 |
| p = 0.60, right | ✅ | +0.18 | 7 | a += 0.18 |
| p = 0.50, either | — | **0.00** | 5 (break-even) | decay only |

**Inconclusive claims settle no one:** stake is returned in full, `brier` stays `NULL`, reputation is untouched.

**Damping:** `damped = true` always in the MVP, *except* when a deterministic check produced ground truth (a URL that does not resolve, a domain younger than the claim). We do not implement automated ground-truth checks in the MVP, so `damped` is effectively always `true` — say this honestly rather than pretending otherwise.

### 9.6 `sql/002_vote_and_rescore.sql` — I4, the one correctness rule

**All score mutation happens here.** JavaScript computes nothing that touches `claims.alpha/beta/score`.

```sql
create or replace function forum.vote_and_rescore(
  p_nullifier  text,
  p_claim_id   uuid,
  p_stance     text,          -- 'support' | 'refute'
  p_confidence double precision,
  p_stake      int,
  p_rep_a      double precision,
  p_rep_b      double precision
) returns table (
  alpha double precision, beta double precision,
  score double precision, voter_count int, weight double precision
)
language plpgsql as $$
declare
  v_reputation   double precision;
  v_stake_factor double precision;
  v_raw          double precision;
  v_cap          double precision;
  v_total        double precision;
  v_n            int;
  v_sup          double precision;
  v_ref          double precision;
begin
  -- 1. Lock the claim. Everything below is serialised per claim.
  perform 1 from forum.claims where id = p_claim_id and status = 'open' for update;
  if not found then
    raise exception 'claim_not_open' using errcode = 'P0002';
  end if;

  -- 2. Compute this voter's raw weight.
  v_reputation   := p_rep_a / (p_rep_a + p_rep_b);
  v_stake_factor := 1 + ln(1 + p_stake);
  v_raw          := v_reputation * v_stake_factor;

  -- 3. Insert. The PRIMARY KEY is the nullifier — duplicate votes are
  --    rejected by the DATABASE, not by an application-level SELECT.
  --    (The reference project's check was TOCTOU-racy.)
  insert into forum.votes
    (nullifier, claim_id, stance, confidence, stake, weight, weight_breakdown)
  values
    (p_nullifier, p_claim_id, p_stance, p_confidence, p_stake, v_raw,
     jsonb_build_object('reputation', v_reputation,
                        'stakeFactor', v_stake_factor,
                        'raw', v_raw));

  -- 4. Recompute the whole claim from scratch. Never incremental — an
  --    incremental update cannot express the per-voter cap correctly.
  select count(*) into v_n from forum.votes where claim_id = p_claim_id;
  v_cap := greatest(0.15, 2.0 / greatest(v_n, 1));

  -- 4a. Water-fill the cap (4 passes converge for any realistic n).
  for i in 1..4 loop
    select sum(least(weight, v_total * v_cap)) into v_total
      from forum.votes where claim_id = p_claim_id;
    exit when v_total is null;
    select sum(weight) into v_total from forum.votes where claim_id = p_claim_id;
    v_total := v_total;   -- first pass seeds the total
  end loop;
  select sum(weight) into v_total from forum.votes where claim_id = p_claim_id;

  -- 4b. Capped sums per side.
  select coalesce(sum(least(weight, v_total * v_cap)), 0) into v_sup
    from forum.votes where claim_id = p_claim_id and stance = 'support';
  select coalesce(sum(least(weight, v_total * v_cap)), 0) into v_ref
    from forum.votes where claim_id = p_claim_id and stance = 'refute';

  -- 5. Add the AI signal, capped at 15% of the total including itself.
  declare
    v_human double precision := v_sup + v_ref;
    v_ai_w  double precision := 0;
    v_hint  text; v_ai_conf double precision; v_disp int;
  begin
    select verdict_hint, confidence, disputes into v_hint, v_ai_conf, v_disp
      from forum.ai_signals where claim_id = p_claim_id
      order by created_at desc limit 1;
    if v_hint is not null and v_human > 0 then
      v_ai_w := least(v_ai_conf,
                      (case when v_disp > 0 then 0.05/0.95 else 0.15/0.85 end) * v_human);
      if    v_hint = 'likely_true'  then v_sup := v_sup + v_ai_w;
      elsif v_hint = 'likely_false' then v_ref := v_ref + v_ai_w;
      end if;
      update forum.ai_signals set weight_contributed = v_ai_w
        where claim_id = p_claim_id;
    end if;
  end;

  -- 6. Persist the posterior. CI is computed in JS (jstat) and written back
  --    by the caller in the SAME transaction.
  update forum.claims c
     set alpha = 1 + v_sup,
         beta  = 1 + v_ref,
         score = (1 + v_sup) / (2 + v_sup + v_ref),
         voter_count = v_n
   where c.id = p_claim_id;

  return query
    select c.alpha, c.beta, c.score, c.voter_count, v_raw
      from forum.claims c where c.id = p_claim_id;
end $$;
```

**Caller responsibility (`server/routes/participate.ts`):** open a transaction, call `vote_and_rescore(...)`, take the returned `alpha`/`beta`, compute `ciLow`/`ciHigh` with `jstat`, `UPDATE forum.claims SET ci_low=…, ci_high=… WHERE id=…`, then check the stability condition (§17.1) and set or clear `stable_since`. **Commit once.** A unique-violation on the nullifier surfaces as HTTP `409 already_voted`.

```ts
/** Fixed 6-dp decimal string. THE ONLY way a number enters a canonical record. */
export const dec6 = (n: number) => n.toFixed(6);

/** RFC 8785 (JCS) subset: keys sorted by UTF-16 code unit, no whitespace,
 *  values restricted to string | integer | string[]. Anything else throws. */
export function jcs(value: unknown): string {
  if (typeof value === "string") return JSON.stringify(value);
  if (typeof value === "number") {
    if (!Number.isInteger(value)) throw new Error("jcs: non-integer number — use dec6()");
    return String(value);
  }
  if (Array.isArray(value)) return "[" + value.map(jcs).join(",") + "]";
  if (value && typeof value === "object") {
    const keys = Object.keys(value as object).sort();   // JS sorts by UTF-16 code unit
    return "{" + keys.map(k => JSON.stringify(k) + ":" + jcs((value as any)[k])).join(",") + "}";
  }
  throw new Error("jcs: unsupported value");
}

export const tallyHash = (nVoters: number, weightFor: number, weightAgainst: number) =>
  sha256Hex(jcs({ nVoters, weightAgainst: dec6(weightAgainst), weightFor: dec6(weightFor) }));

/** leaf = SHA256(0x00 ‖ JCS(record)) */
export const leafHash = (r: VerdictRecord) => sha256HexBytes(concat([0x00], utf8(jcs(r))));
```

### 10.2 Merkle tree (I8)

```ts
const NODE = 0x01;

export function buildTree(leaves: string[]): string[][] {
  if (leaves.length === 0) return [[]];
  const levels: string[][] = [leaves];
  while (levels[levels.length - 1].length > 1) {
    const prev = levels[levels.length - 1];
    const next: string[] = [];
    for (let i = 0; i < prev.length; i += 2) {
      const l = prev[i];
      const r = i + 1 < prev.length ? prev[i + 1] : prev[i];   // duplicate the last (I8)
      next.push(sha256HexBytes(concat([NODE], hexBytes(l), hexBytes(r))));
    }
    levels.push(next);
  }
  return levels;
}

export const rootOf = (levels: string[][]) => levels[levels.length - 1][0];

export function proofFor(levels: string[][], index: number): string[] {
  const proof: string[] = [];
  let idx = index;
  for (let lv = 0; lv < levels.length - 1; lv++) {
    const level = levels[lv];
    const sib = idx % 2 === 0 ? Math.min(idx + 1, level.length - 1) : idx - 1;
    proof.push(level[sib]);
    idx = Math.floor(idx / 2);
  }
  return proof;
}

/** Must produce byte-identical results to the Solidity verify() in §13.2. */
export function verifyProof(leaf: string, proof: string[], index: number, root: string) {
  let h = leaf;
  for (let i = 0; i < proof.length; i++) {
    h = ((index >> i) & 1) === 0
      ? sha256HexBytes(concat([NODE], hexBytes(h), hexBytes(proof[i])))
      : sha256HexBytes(concat([NODE], hexBytes(proof[i]), hexBytes(h)));
  }
  return h === root;
}
```

| **T1 Guest** | Turnstile + passkey | post claims, add evidence | **0** |
| **T2 Verified** | T1 + redeem a one-time invite code | vote, stake, earn reputation, mint invites | 1.0 × reputation |

**Steps are independent.** Skipping the invite leaves you at T1. Reading has zero friction; only *influence* is gated.

### 12.2 Enrolment flow — `POST /api/enrol/begin` → `POST /api/enrol/finish`

```
1. Visitor clicks "Join"
2. Cloudflare Turnstile (invisible for most)     [skipped if not configured, dev only]
3. Create a passkey  — WebAuthn platform authenticator, attestation: "none"
4. Optionally paste/scan a one-time invite code
5. Account created: random UUID + handle "fox-8813", 10 points, T1 or T2
6. Backup codes shown ONCE
```

**`begin`**: verify Turnstile → `generateRegistrationOptions({ rpName, rpID, userName: <ephemeral random>, attestationType: "none", authenticatorSelection: { residentKey: "preferred", userVerification: "preferred" } })`. **Store the challenge in a short-lived signed cookie, not in a table** — 5-minute JWT in `attest_chal`, httpOnly, SameSite=Lax. This avoids a sessions table entirely.

**`finish`**: read the challenge cookie → `verifyRegistrationResponse` → then, **in one transaction**:

1. If an invite code was supplied: `SELECT … FROM enrolment.invites WHERE redeemed_at IS NULL AND NOT revoked AND expires_at > now() FOR UPDATE`, `argon2.verify` each candidate against the supplied code, mark `redeemed_at = now()`. Tier = 2. Otherwise tier = 1.
2. `INSERT INTO forum.accounts` with `pseudonym_id` defaulted by the database (`gen_random_uuid()` — **I1**), `points = 10`.
3. Generate 8 backup codes, store `argon2id` hashes, return the plaintext **once**.
4. Issue the session cookie.

> **The invite lookup must not leak.** Do not index invites by a plain hash of the code — argon2 is salted, so you cannot look up by hash. Fetch unredeemed non-expired invites (a handful at beta scale) and verify each. At a few hundred invites this is fine; above that, add a fast non-secret prefix index. Say so in a code comment.

**The QR does not require two devices.** The invite is *a code*; the QR is one convenient transport. On a phone the user pastes it or follows `https://<host>/join?i=<code>`. Nobody is ever required to own two devices — this was a genuine flaw in the original design and must not reappear in the UI copy.

### 12.3 Session — `server/session.ts`

Stateless signed JWT (`jose`, HS256, `SESSION_SECRET`), 7-day expiry, payload `{ sub: pseudonymId, tier }`. Cookie `attest_session`: `httpOnly`, `secure` in production, `SameSite=Lax`, `path=/`.

No sessions table. **No PII in the token** — the pseudonym is already meaningless (I1).

Middleware: `requireAuth` → 401 `not_authenticated`; `requireT2` → 403 `tier_required` with `{ needed: 2 }` so the client can show the right prompt.

### 12.4 Login — `POST /api/auth/begin` → `/api/auth/finish`

Usernameless: `generateAuthenticationOptions({ rpID, userVerification: "preferred" })` with **no `allowCredentials`**. On finish, look the account up by the returned credential ID, verify against `passkey_pubkey`, and **update `passkey_counter`** (reject a counter that goes backwards — that is a cloned-authenticator signal).

### 12.5 Recovery

Backup codes only, shown once at enrolment, `argon2id`-hashed, single use. Losing them means losing the account — that is the honest trade for having no identity on file. **Do not add email recovery.** There is no email.

### 12.6 Rate limits — `server/ratelimit.ts` (Postgres, not Redis)

```ts
/** Atomic fixed-window counter. Returns true if the action is allowed. */
export async function checkRate(key: string, action: keyof typeof RATE_LIMITS) {
  const { limit, windowMinutes } = RATE_LIMITS[action];
  const { rows } = await db.execute(sql`
    insert into enrolment.rate_limits (key, action, count, window_start)
    values (${key}, ${action}, 1, now())
    on conflict (key, action) do update set
      count = case when enrolment.rate_limits.window_start < now() - (${windowMinutes} || ' minutes')::interval
                   then 1 else enrolment.rate_limits.count + 1 end,
      window_start = case when enrolment.rate_limits.window_start < now() - (${windowMinutes} || ' minutes')::interval
                   then now() else enrolment.rate_limits.window_start end
    returning count`);
  return Number(rows[0].count) <= limit;
}
```

Key on the pseudonym for authenticated actions, on `ipKey(req.ip)` for pre-account actions. **Never the raw IP.** On rejection return `429 { error: "rate_limited", retryAfterSeconds }`.

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract AttestAnchorRegistry {
    struct Anchor { bytes32 root; uint64 leafCount; uint64 timestamp; }

    mapping(uint64 => Anchor) public anchors;
    uint64  public latestEpoch;
    address public anchorer;

    event Anchored(uint64 indexed epoch, bytes32 root, uint64 leafCount);

    error NotAuthorised();
    error AlreadyAnchored();

    constructor(address _anchorer) { anchorer = _anchorer; }

    function submitAnchor(uint64 epoch, bytes32 root, uint64 leafCount) external {
        if (msg.sender != anchorer) revert NotAuthorised();
        if (anchors[epoch].timestamp != 0) revert AlreadyAnchored();
        anchors[epoch] = Anchor(root, leafCount, uint64(block.timestamp));
        if (epoch > latestEpoch) latestEpoch = epoch;
        emit Anchored(epoch, root, leafCount);
    }

    function verify(uint64 epoch, bytes32 leaf, bytes32[] calldata proof, uint256 index)
        external view returns (bool)
    {
        bytes32 h = leaf;
        for (uint256 i = 0; i < proof.length; i++) {
            h = (index >> i) & 1 == 0
                ? sha256(abi.encodePacked(bytes1(0x01), h, proof[i]))
                : sha256(abi.encodePacked(bytes1(0x01), proof[i], h));
        }
        return h == anchors[epoch].root;
    }
}
```

### 14.5 `/verify` — the demo centrepiece

Works for a stranger with no account and no wallet:

1. Paste a claim ID, or drop a downloaded `certificate.json`.
2. `GET /api/verify/:claimId` → `{ record, leaf, epoch, index, proof, anchor }`.
3. **Recompute the leaf hash in the browser** from `record` (`sha256(0x00 ‖ jcs(record))`) and check it matches `leaf`.
4. Walk the proof to a root with `verifyProof`.

6. ✅ green with a Basescan link, or ❌ red with the exact step that failed.

**The Tamper button** — always visible, not dev-only:

**This single interaction will do more for your score than any slide.** Make it obvious, make it fast, and make the failure loud (red, shake animation, the two hashes side by side with the differing bytes highlighted).

### 15.2 The prompt (`AI_PROMPT_VERSION = "p1"` — bump it on any edit)

```
You are an evidence-gathering assistant for a public fact-checking platform.
You are NOT the judge. Your output is one capped signal among many, and human
voters can and will overrule you.

Analyse the claim below and return JSON only.

SUBJECT KIND: {url|phone|text}
SUBJECT: {normalised subject}
CLAIM: {statement}
DETAIL: {detail or "(none)"}

Rules:
- Use ONLY what is in the text above plus general world knowledge. You have no
  web access. If you cannot assess it, return "unverifiable" with confidence 0.
- "confidence" is your probability that verdictHint is correct, 0.0 to 1.0.
  Be conservative. Above 0.8 requires a near-certain structural giveaway
  (for example an obvious lookalike domain).
- "rationale" is ONE plain sentence, at most 30 words, written for a general
  audience with no technical background. No jargon, no hedging boilerplate.
- "redFlags" is 0 to 4 short noun phrases, each at most 5 words.
  Examples: "urgency language", "lookalike domain", "unverifiable payout claim".

- Never state a person is guilty of a crime. Describe the message, not the human.
```

### 15.3 Handling

- Timeout 8 s. On any failure — 429, timeout, malformed JSON, schema mismatch — insert the fixture signal from §5.3 and **carry on**. Never fail the claim submission because of the AI.
- Clamp `confidence` into `[0, 1]`. Truncate `rationale` to 200 chars and `redFlags` to 4 items of 40 chars.
- The signal's `weight_contributed` is computed by `vote_and_rescore` (§9.6), **not** by this module. It stays 0 until at least one human votes (I9).
- Every AI contribution is labelled in the UI with its model and prompt version.
- `POST /api/ai-signals/:id/dispute` increments `disputes`; the next rescore drops the cap to 5 % and the card renders a visible "disputed" flag.
- **The AI can never resolve a claim, and can never reject a submission.** The reference project lets its analyser hard-reject posts — that is an unaccountable AI gate on speech, and we do not repeat it.

## 17. Scheduled jobs — `server/routes/jobs.ts`

Both are plain authenticated `POST`s. Auth: `X-Job-Token` header compared against `JOB_TOKEN` with `crypto.timingSafeEqual`. **Both must be idempotent.**

Also expose them behind `requireT2` as `POST /api/jobs/resolve?manual=1` so you can trigger them live on stage without waiting for cron. **Do this — never let a demo depend on an external scheduler's timing.**

### 17.1 `POST /api/jobs/resolve` — every 5 minutes

For each `status = 'open'` claim:

1. Recompute `P(θ ≥ 0.75)` and `P(θ ≤ 0.25)` from `alpha`/`beta`.
2. Evaluate all three conditions:
   - **Confidence** — `P(θ ≥ τ_verify) ≥ 0.90` or `P(θ ≤ τ_refute) ≥ 0.90`
   - **Participation** — ≥ 3 distinct T2 voters
   - **Stability** — the condition has held for ≥ 30 minutes
3. If confidence + participation hold and `stable_since IS NULL` → set `stable_since = now()` and stop. If they stop holding → clear `stable_since`.
4. If all three hold → **settle** (§17.2).
5. If `now() > expires_at` → settle as `inconclusive` (a legitimate outcome, clearly worded — not a failure).

The 5-minute cadence also doubles as the keep-warm ping that stops the database autosuspending.

### 17.2 Settlement — `sql/004_settle_claim.sql`, one transaction

1. `UPDATE forum.claims SET status = …, resolved_at = now()`.
2. For each vote: `y = (status === 'verified') ? 1 : 0`; `p = pTrue(stance, confidence)`; `Δc = brier(p, y)`; write `brier`, `settled_at`.
3. Return `payout(stake, Δc)` points to the voter; decrement `points_staked`.
4. `updateReputation(repA, repB, Δc, damped = true)`.
5. **Inconclusive:** return every stake in full, leave `brier` NULL, touch no reputation.
6. Build the `VerdictRecord` (§10.1), `payloadHash = sha256(jcs(record))`, call `append_ledger_event('verdict', …, epoch = floor(now/900))`, and store `anchor_epoch` on the claim.

**Mapping the vote to the voter without a foreign key (I3):** the vote row holds only a nullifier. To settle, iterate over T2 accounts and recompute `nullifier(pseudonymId, claimId)` for each — at beta scale this is a few dozen HMACs per claim and is instantaneous. Do **not** add an account column to `votes` to make this easier; that column is the whole privacy property. Write a comment saying exactly that, because it is the first thing a future contributor will try to "optimise".

### 17.3 `POST /api/jobs/anchor` — every 15 minutes

1. `currentEpoch = floor(now / (EPOCH_MINUTES * 60))`.
2. Find every epoch `< currentEpoch` that has `ledger_events` but no `confirmed` row in `forum.anchors`. **Process all of them, not just the latest** — a missed tick then self-heals instead of leaving a permanent gap.
3. For each: load that epoch's events ordered by `seq`, compute `leaf = sha256(0x00 ‖ jcs(payload))` for each, `buildTree`, `rootOf`, write `leaf_index` back onto each event, upsert `forum.anchors` as `pending`.
4. If `features.chain`: `submitAnchor(epoch, root, leafCount)`, wait for the receipt, set `status = 'confirmed'` with `tx_hash` and `block_number`. If the tx reverts with `AlreadyAnchored`, read the on-chain anchor and mark it `confirmed` anyway — that is a successful outcome, not an error.
5. If not: `status = 'skipped_no_chain'`.

**cron-job.org setup** (per `setup.md` §10): two jobs, `POST`, header `X-Job-Token: <JOB_TOKEN>`, at 5 and 15 minutes. Use *Test run* immediately and confirm a 200. GitHub Actions' `schedule:` is best-effort and routinely 5–30 minutes late; Vercel Hobby cron allows once per day. Neither is demonstrable on stage.

## 20. Trust and safety

*"No central authority decides truth"* does **not** mean *"no operator removes illegal content."* CSAM, terrorist material and doxxing are not matters of crowd opinion, and a public product needs a stated answer.

Operator removal sets `status = 'removed'`, replaces the body with a tombstone, and — crucially — **writes a `removal` event into the same hash chain, anchored like everything else.** So even the operator's exercise of power is publicly auditable and countable. That turns the obvious weakness into a feature, and it is worth thirty seconds of the pitch.

**Text and URLs only. No image uploads.** This keeps the surface small by construction and removes the entire CSAM risk from a hackathon demo.

Implement as `POST /api/admin/remove/:claimId` behind the `JOB_TOKEN` header. No admin UI — a curl command is enough for the MVP.

## 23. Explicitly out of scope — do not build these

Building any of these costs days and demonstrates nothing at beta scale. If you find yourself writing one, stop.

Device-integrity attestation (Play Integrity / App Attest) · blind-signature credentials (RSA-BSSA) · two separate databases · Redis · commit–reveal voting · voter-similarity clustering and the independence discount `D_i` · proof-of-work captcha · tiers T3/T4 · image upload and moderation · evidence-quality weighting `Q_e` · claim-score time decay `e^{-Δt/τ}` · i18n/RTL · Sentry · Alchemy · Cloudinary · **any email or SMS of any kind, including OTPs** · wallet connection for end users · a native mobile app · vector search for similar claims · admin dashboard UI.

**There is no email in this product.** If you find yourself installing an email library, you have misread the design.

## 24. Failure modes — check here first

| Symptom | Cause / fix |
|---|---|
| `passkey creation failed` | `RP_ID` mismatch. Must be the bare registrable host — no scheme, no port — and identical at register and login. #1 cause. |
| WebAuthn silently unavailable | Not HTTPS and not `localhost`. Replit's deployed URL is HTTPS; use it. |
| `/verify` red on a valid claim | Canonicalisation drift. Check: `score` is a **6-dp string**, not a float; leaf uses `0x00` and nodes `0x01`; odd-node duplication matches on both sides; the browser and server `sha256` agree. |
| Browser leaf ≠ server leaf | `crypto.subtle` is async and returns an `ArrayBuffer` — a missing `await` yields a hash of `"[object Promise]"`. |
| Score jumps when a second voter arrives | The cap is binding at small n. Confirm `applyVoterCap` uses `max(0.15, 2/n)` (§9.2). |
| Reputation rises for everyone | You are using the raw Brier, not the centred one. `brier(0.5, y)` must be `0` (§9.5). |
| Points inflate to dominance | Same cause — check `payout()` uses `clamp(1 + 2Δc, 0, 2)`, not `20 × stake × Δ`. |
| Two simultaneous votes corrupt the score | Scoring is not inside `vote_and_rescore` with `FOR UPDATE` (I4). |
| `insufficient funds for gas` | Faucet the anchorer wallet. Check on sepolia.basescan.org. |
| Anchor tx pending forever | Public RPC congested. Bump gas, or swap `RPC_URL` for a free Ankr/Alchemy endpoint. |
| Gemini 429 | Free-tier per-minute limit. One call per claim at submission, cached forever. Never call on render. |
| Cron returns 401 | `X-Job-Token` missing or mismatched. |
| First request takes 3 s | Database autosuspend. The 5-minute resolve job keeps it warm. |
| Turnstile always fails | Domain not in the widget's allow-list, or site/secret keys swapped. Add both the `.replit.dev` dev host and the `.replit.app` production host. |

## 25. Open decisions (defaults are already set — change only with data)

1. **Product name.** "Attest" is a placeholder. Change it in `shared/strings.ts` only.
2. **Resolution thresholds.** `τ = 0.75`, 3 voters, 30-minute stability. Tune against seeded data so a claim can actually resolve during a 5-minute demo — this is the one number most likely to need adjusting on the day.
3. **Anchor cadence.** 15 minutes is a guess. Align it with whatever makes the demo timing work.
4. **Points economy.** 10 starting, `clamp(1 + 2Δc, 0, 2) × stake` payout. Sanity-check with the seed script that a run of correct votes does not inflate one account to dominance within a 20-person beta.
5. **Seed content.** Real scam patterns beat invented ones. Nothing defamatory about a named individual.
